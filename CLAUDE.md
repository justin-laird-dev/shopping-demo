## Development Log

Maintain `DEVELOPMENT_LOG.md` at the project root as a running narrative of this project's build process — intended for eventual presentation. After completing a notable milestone (an OpenSpec change is archived, a significant bug is diagnosed and fixed, a meaningful methodology lesson emerges), append an entry covering: what happened, why, any problem encountered and its root cause, and — where relevant — a candid observation about the OpenSpec-driven methodology itself (a strength it demonstrated, or friction/overhead it introduced). Keep entries factual and concise; this is a journal, not marketing copy. Don't wait to be asked — update it proactively as part of finishing the work, the same way you'd update tasks.md.
